# BridgeFinder

Telegram-бот, который по тикеру криптовалюты (`USDT`, `ETH`, `SOL`, `WBTC`, ...)
показывает кроссчейн-мосты, поддерживающие этот токен, вместе со списком сетей
и прямой ссылкой на сервис.

## Возможности

- `/start` — приветствие и краткая инструкция.
- Текстовый ввод тикера, регистронезависимый (`usdt`, `Usdt`, `USDT` — одно и то же).
- Ответ со списком мостов, поддерживаемых сетей и ссылок.
- Поиск не ограничен коротким списком: если тикера нет в курируемом справочнике,
  бот проверяет его наличие через живой индекс токенов Li.Fi, построенный по
  **всем** сетям, которые отслеживает Li.Fi (не по фиксированному короткому
  списку) — это покрывает подавляющее большинство активно торгуемых токенов
  тир-1/2/3, а не только десяток вручную выбранных. Если токен найден в 2+
  сетях, бот показывает универсальные кросс-чейн агрегаторы с пометкой
  «определено автоматически».
- Понятное сообщение, если токен не найден нигде, с подсказкой похожих тикеров
  при опечатке.
- `/stats` — статистика для администраторов: уникальные пользователи, количество
  запросов за день/месяц, топ тикеров.
- Фоновая синхронизация со списком сетей мостов DefiLlama и с индексом токенов
  Li.Fi раз в `SYNC_INTERVAL_HOURS` часов (по умолчанию 8), с кэшированием в Redis.

## Архитектура

```
app/
  config.py              # настройки из переменных окружения
  main.py                # точка входа: бот, синхронизация, DI
  data/bridges_seed.json # справочник тикер -> мосты -> сети/ссылки
  bot/
    formatting.py        # шаблоны сообщений
    handlers/
      start.py            # /start
      search.py           # обработка тикера
      stats.py            # /stats (только для админов)
  services/
    bridge_repository.py # поиск мостов по тикеру (curated + auto-detected), фаззи-подсказки
    cache.py              # обёртка над Redis с fallback в память
    defillama_client.py   # клиент DefiLlama Bridges API
    lifi_client.py         # клиент публичного Li.Fi API
    sync.py                # фоновая синхронизация сетей мостов (DefiLlama)
    token_sync.py           # фоновая синхронизация индекса тикер -> сети (Li.Fi)
  db/
    repository.py          # SQLite: пользователи, лог запросов, статистика
```

### Источники данных

Поиск устроен в два слоя:

1. **Курируемый слой.** Сопоставление «тикер → какие мосты его поддерживают»
   и официальные ссылки на мосты хранятся в справочнике
   `app/data/bridges_seed.json`, потому что бесплатный DefiLlama API не
   отдаёт привязку конкретных токенов к мостам. Список сетей для каждого
   моста при этом обновляется живыми данными: **DefiLlama Bridges API**
   (`https://bridges.llama.fi/bridges`) отдаёт список активных мостов и
   сети, в которых они сейчас работают, — `services/sync.py` тянет это раз
   в `SYNC_INTERVAL_HOURS` часов и обновляет кэш.
   Сюда же входят официальные мосты для нативных не-EVM/не-Solana сетей —
   **TON** (`bridge.ton.org`), **Bitcoin** через tBTC (`threshold.network`),
   **Cosmos Hub** через Axelar, **Polkadot** через Snowbridge, **NEAR** через
   Rainbow Bridge, а также Aptos/Sui через Wormhole. Li.Fi эти сети не
   отслеживает (это EVM/Solana-ориентированный агрегатор), поэтому без
   такого курируемого дополнения, например, `TON` находился бы только как
   wrapped-версия на EVM-сетях — без самой сети TON в ответе.
2. **Слой автоопределения.** Для любого тикера, которого нет в курируемом
   справочнике (например, `LSK`), `services/token_sync.py` раз в
   `SYNC_INTERVAL_HOURS` часов запрашивает у **Li.Fi API**
   (`https://li.quest/v1/chains` и `/v1/tokens`) список **всех** мейннетов,
   которые отслеживает Li.Fi (десятки сетей, а не фиксированные ~10-12), и
   строит индекс «тикер → в каких из них токен реально существует». Если
   токен найден на 2+ сетях, `BridgeRepository` показывает его как
   доступный через универсальные кросс-чейн агрегаторы (LI.FI/Jumper, Rango,
   Bungee, Squid Router) — такие сервисы комбинируют DEX-ликвидность с
   доступными мостами и могут провести практически любой токен между сетями,
   где он существует, в отличие от узких ликвидностных мостов вроде
   Stargate/Hop, которые поддерживают только заранее одобренный список
   токенов. Это эвристика («существует в 2+ сетях» ≠ гарантированный маршрут
   с хорошей ликвидностью), поэтому такие результаты явно помечаются в
   ответе бота как «определено автоматически» с просьбой свериться на сайте
   агрегатора перед переводом.
3. Если и курируемый, и автоопределённый слой ничего не находят — бот
   честно отвечает, что мостов не нашёл, и предлагает похожие тикеры.
4. Если DefiLlama или Li.Fi временно недоступны, синхронизация просто
   логирует предупреждение и оставляет предыдущие данные — бот продолжает
   отвечать тем, что уже есть в кэше/справочнике.

### Кэш и хранилище

- **Redis** кэширует список сетей по каждому мосту (обновляется фоновой
  синхронизацией). Если Redis недоступен, `CacheClient` прозрачно переключается
  на кэш в памяти процесса, чтобы бот не переставал отвечать.
- **SQLite** (`aiosqlite`) хранит профили пользователей и лог запросов для
  команды `/stats`.

## Запуск локально

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt

cp .env.example .env
# впишите BOT_TOKEN и ADMIN_IDS в .env

python -m app.main
```

Redis для локального запуска можно поднять отдельно (`docker run -p 6379:6379 redis:7-alpine`)
или просто не запускать — бот продолжит работать на in-memory кэше.

## Запуск в Docker

```bash
cp .env.example .env
# впишите BOT_TOKEN и ADMIN_IDS в .env

docker compose up -d --build
```

`docker-compose.yml` поднимает `redis` и `bot` с политикой `restart: unless-stopped`
для бесперебойной работы 24/7.

## Тесты

```bash
pytest
```

## Переменные окружения

| Переменная                | Обязательна | По умолчанию                     | Описание                                   |
|----------------------------|:-----------:|-----------------------------------|---------------------------------------------|
| `BOT_TOKEN`                | да          | —                                  | Токен Telegram-бота от @BotFather           |
| `ADMIN_IDS`                | нет         | `""`                               | Telegram user id админов через запятую      |
| `REDIS_URL`                | нет         | `redis://localhost:6379/0`         | Строка подключения к Redis                  |
| `DATABASE_PATH`            | нет         | `data/bridgefinder.db`             | Путь к файлу SQLite                         |
| `DEFILLAMA_BASE_URL`       | нет         | `https://bridges.llama.fi`         | Базовый URL DefiLlama Bridges API           |
| `LIFI_BASE_URL`            | нет         | `https://li.quest`                 | Базовый URL публичного Li.Fi API            |
| `SYNC_INTERVAL_HOURS`      | нет         | `8`                                 | Период фоновой синхронизации, часы         |
| `REQUEST_TIMEOUT_SECONDS`  | нет         | `5`                                 | Таймаут быстрых HTTP-запросов (список мостов) |
| `LIFI_SYNC_TIMEOUT_SECONDS`| нет         | `30`                                | Таймаут запроса токенов Li.Fi по всем сетям сразу |
| `LOG_LEVEL`                | нет         | `INFO`                              | Уровень логирования                         |
